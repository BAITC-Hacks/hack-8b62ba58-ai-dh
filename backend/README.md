# Сервер Challenge Hub

Этот сервер запускает весь проект: отдаёт интерфейс из соседней папки `../frontend`, обслуживает API и сохраняет общие данные в SQLite. Общие инструкции запуска находятся в [README проекта](../README.md).

Нужен Node.js 24 или новее. Внешних пакетов нет, установка зависимостей не требуется. Для запуска отдельно из папки `backend`:

```sh
node --env-file-if-exists=.env src/server.ts
```

Откройте http://127.0.0.1:4000. Проверка состояния: http://127.0.0.1:4000/api/health. Проверки сервера: `node --test tests/api.test.ts` из папки `backend`; тесты используют временные базы и не меняют рабочие данные. Если npm доступен, также работают `npm start` и `npm test`.

Настройки можно сохранить в `backend/.env` по образцу `env.example`. По умолчанию сервер доступен только на этом компьютере; база создаётся в `backend/data/ai-sana.sqlite`. `CORS_ORIGINS` задаёт дополнительные разрешённые адреса интерфейса. Адреса самого сервера на настроенном порту разрешены автоматически. Настройки и база не раздаются через HTTP.

## Данные и API

Ответы имеют вид `{data: ...}`, ошибки — `{error: {code, message, requestId}}`. Каталог: `GET /api/tasks`. Справочники полей, тем и уровней: `GET /api/meta`. Профили и баллы команд: `GET /api/teams`.

Для действий бизнеса используется `X-Demo-Role: business`, для команды — `X-Demo-Role: student` и `X-Team-Id` из `/api/teams`. Это демонстрационный выбор роли, а не проверка учётной записи. Настоящая авторизация и внешний AI-провайдер пока не подключены. Помощник работает локально: сохраняет введённый текст и задаёт вопросы о недостающих данных.

Работа с задачей: создать черновик (`POST /api/tasks` с `draft` и `topic`), уточнить (`POST /api/tasks/:id/clarify`), сохранить поля (`PATCH /api/tasks/:id`), подтвердить (`POST /api/tasks/:id/confirm`), опубликовать (`POST /api/tasks/:id/publish`). Каждый ответ содержит новую `revision`; следующий запрос изменения передаёт её как `expectedRevision`. При конфликте сервер возвращает 409. После редактирования опубликованной задачи каталог сохраняет прежнюю версию до повторного подтверждения и публикации.

Предложения команд: `GET/POST /api/tasks/:id/proposals`. Для отправки обязательны `idea`, `plan`, `deadline`, `url`. Решение бизнеса: `PATCH /api/proposals/:id` с `expectedRevision` и `status` (`selected` или `rejected`). Подтверждение выполненного этапа: `POST /api/tasks/:id/milestones/confirm` с `teamId`, `stage` (`prototype` или `pilot`) и `evidence`; каждый этап приносит 25 баллов, повторы не удваивают награду.

Примеры HTTP-запросов находятся в [docs/api.http](docs/api.http), типизированный клиент — в [docs/client.ts](docs/client.ts). Клиент по умолчанию обращается к серверу на адресе открытой страницы. Начальные данные создаёт `src/domain.ts`; `docs/seed.json` служит примером формата и не импортируется автоматически.
