# Передача проекта команде

Интерфейс и сервер объединены. Запуск из корня проекта: START.cmd; сайт и API доступны по одному адресу http://127.0.0.1:4000. Подробные инструкции — в корневом README.md.

## Фронтенд

frontend/api.js — используемый браузером клиент. Он читает {data: ...} и {error: {message, code}}, передаёт демо-роль, команду и текущую expectedRevision. frontend/app.js связывает формы с API. Задачи и отклики хранятся в SQLite, а не в localStorage.

Метаданные карточки, темы и уровни приходят из /api/meta. docs/client.ts — дополнительный типизированный клиент для будущего TypeScript-фронтенда; он использует адрес текущего сайта по умолчанию.

## Бэкенд

backend/src/app.ts содержит API и разрешённые статические маршруты. database.ts управляет SQLite, domain.ts — рейтингом и AI-демо, config.ts — разрешёнными адресами сайта. Рабочая база: backend/data/ai-sana.sqlite.

Изменения карточки: create → clarify → update → ручное confirm → publish. После каждой операции нужно использовать новую revision. При 409 нельзя автоматически повторять запись поверх новых данных.

Команда отправляет предложение через /proposals; бизнес выбирает или отклоняет его. Баллы начисляются только выбранной команде после подтверждения этапа с описанием результата проверки.

## AI

src/domain.ts содержит AI_PROMPT, demoAnalyze, parseAIResponse, analyze. В createApp(db, {aiProvider}) можно передать серверный провайдер. Секретный ключ хранится только на сервере. Неизвестные факты остаются пустыми; публикацию подтверждает пользователь.

Внешний OpenAI подключён через src/ai_service.js: generateAssessment и два системных промпта. Ключ хранится в backend/.env. Без ключа используется демо. Выбор роли остаётся демонстрационным.

## Проверка

Из корня проекта: TEST.cmd или node --test backend/tests/*.test.ts. Тестовые базы отделены от рабочей. Для совместной проверки по локальной сети настройте HOST и CORS_ORIGINS по корневому README; localhost на разных компьютерах указывает на разные машины.
